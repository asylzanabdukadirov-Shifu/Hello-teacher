3. МИССИЯ 1 — EDIT DISTANCE

Функция: Strains.editDistance(a, b).
Разрешены вставка, удаление и замена; каждое действие стоит 1.
Пример: ACGT → AGT. Удаляем C, ответ 1.

Создаём таблицу d размером (a.length()+1) × (b.length()+1).
d[i][j] — минимум действий, превращающих первые i букв A в первые j букв B.
Пустая строка тоже учитывается:
  d[i][0] = i: удаляем i букв;
  d[0][j] = j: вставляем j букв.

В каждой следующей клетке берём минимум из трёх вариантов:
  d[i-1][j] + 1       — удалить последнюю букву A;
  d[i][j-1] + 1       — добавить последнюю букву B;
  d[i-1][j-1] + cost  — оставить одинаковую букву или заменить различную.
cost равен 0 при равенстве букв и 1 при различии.

Индексы букв: i-1 и j-1, потому что строки начинаются с 0, а строка 0
таблицы соответствует пустому префиксу. Ответ — в правом нижнем углу.
Время и память: O(a*b), поскольку заполняется полная таблица.
Почему нельзя просто посчитать разные буквы на одинаковых позициях?
Потому что вставка или удаление сдвигает оставшуюся часть строки.

4. МИССИЯ 2 — LCS

Функция: Strains.lcsLength(a, b).
Подпоследовательность сохраняет порядок букв, но разрешает пропуски.
Подстрока должна идти подряд. AGT — подпоследовательность ACGT,
но не его подстрока.

lcs[i][j] — длина LCS первых i и j букв. Пустая строка имеет LCS 0.
Если последние буквы совпали:
  lcs[i][j] = lcs[i-1][j-1] + 1.
Иначе:
  lcs[i][j] = max(lcs[i-1][j], lcs[i][j-1]).
То есть пробуем пропустить букву одной из строк и выбираем лучший вариант.

У тебя LCS = 1019, хотя на одинаковых индексах совпали только 289 букв.
LCS учитывает совпадения после сдвигов. Время и память: O(a*b).
Если нужна только длина, теоретически достаточно двух строк таблицы;
здесь оставлена полная таблица, как в задании.

5. МИССИЯ 3 — ПРЕФИКС-ФУНКЦИЯ И KMP

Функции: Marker.prefixFunction(p), Marker.findAll(text, p).
pi[i] — длина самого длинного собственного префикса p[0..i], который
одновременно является его суффиксом. «Собственный» означает короче всей
рассматриваемой строки, иначе ответ всегда был бы её длиной.

Для твоего маркера:
  буква: A T C G C A A T C
  pi:    0 0 0 0 0 1 1 2 3
Последняя тройка означает border ATC: это и начало, и конец маркера.

KMP хранит matched — сколько букв маркера уже совпало. Если следующая
буква не подошла, matched становится pi[matched-1]. Используется уже
известный совпавший суффикс: указатель текста не возвращается назад.
Если matched достиг длины маркера, найдено вхождение с началом
i - p.length() + 1. После этого тоже делаем откат к pi[matched-1].

Почему после полного совпадения нельзя просто обнулить matched?
Пример: AA внутри AAA. Правильные позиции — 0 и 1, они перекрываются.
Сохранив border длины 1, мы не теряем второе вхождение.
Время: O(n+m), где n — длина текста, m — длина маркера.
Память: O(m+h), где h — количество возвращаемых позиций.
Пустой маркер в дополнительном соглашении встречается на всех n+1 границах;
в личных данных из задания маркер непустой.

6. МИССИЯ 4 — RABIN–KARP

Функция: Marker.sharedWords(a, b, k). В Main k = 12.
Берём каждое окно из k букв в A и проверяем, встречается ли оно в B.
Считаются позиции A, а не различные слова и не число пар совпадений.
AAAAAA и AAAA при k=3 дают 4: окна A начинаются в позициях 0, 1, 2, 3.

Окно представляем числом — полиномиальным хешем. В реализации BASE=257,
MOD=1000000007. Вычисляем хеш первого окна и BASE^(k-1) по модулю.
При сдвиге на одну букву:
  1) вычитаем старую букву, умноженную на BASE^(k-1);
  2) умножаем остаток на BASE;
  3) прибавляем новую букву;
  4) берём остаток по MOD, корректируя отрицательное значение.
Это O(1) операций на сдвиг, а не пересчёт всех k букв.

В HashMap хранятся хеши окон B и списки их начальных позиций.
Если хеш окна A найден, сравниваем реальные буквы с кандидатами B.
При первом настоящем совпадении увеличиваем ответ и прекращаем поиск
для этой позиции A. Несколько совпадений в B не завышают ответ.

Одинаковые хеши не гарантируют одинаковые строки — возможна коллизия.
Реальный пример: CAGAGGGCGCAC и CAACGTGGGAGT различны, но при выбранной
формуле имеют одинаковый хеш 128891000. Это включено в тесты.

При фиксированном k=12 и обычном распределении хешей ожидается O(a+b).
Точнее: O(a+b+c*k), где c — число сравнённых кандидатов. Если много разных
слов попадут в одну корзину, реализация со списками может дойти до
O(a*b*k). Память — O(b). При повторении настоящих одинаковых слов цикл
останавливается уже на первом совпадении.

7. МИССИЯ 5 — ДИНАМИКА НА ДЕРЕВЕ

Функция: Outbreak.cheapestTests(n, nb, cost).
Надо выбрать вершины так, чтобы у каждого ребра хотя бы один конец был
выбран, а сумма цен была минимальна. Это минимальное взвешенное вершинное
покрытие дерева. Искать самого «нулевого пациента» не требуется.

Корень — вершина 0. Рёбра не направлены, поэтому при обходе запоминаем
parent и не возвращаемся в него. Для каждого v храним суммы для поддерева:
  take[v] — минимум, если v тестируем;
  skip[v] — минимум, если v не тестируем.

Сначала обрабатываем детей, потом родителя:
  take[v] = cost[v] + сумма min(take[child], skip[child]);
  skip[v] = сумма take[child].
Если v не выбран, каждый ребёнок обязан быть выбран: иначе ребро между
ними останется без теста. Если v выбран, для ребёнка берём более дешёвый
вариант. Для листа take=его цена, skip=0.

Ответ — min(take[0], skip[0]). Для картинки нужны сами выбранные люди,
поэтому rebuild идёт от корня к детям и восстанавливает выбор.
При равных ценах возможны разные оптимальные наборы; этот код выбирает
skip, если выбор не навязан непроверенным родителем.

Main запускает алгоритм дважды:
  со всеми ценами 1 — минимальное количество людей: 28;
  с реальными ценами — минимальная общая цена: 129.

Жадный метод неверен: в звезде центр имеет три связи и стоит 10,
а каждый из трёх листьев стоит 1. Выбрать центр с наибольшим числом связей
стоит 10, тогда как все листья вместе стоят 3.

longestChain считает диаметр. Для каждой вершины берём две самые длинные
ветви вниз. Их сумма — самый длинный путь через эту вершину. Максимум по
всем вершинам — ответ. Считаются рёбра: 0-1-2-3 имеет длину 3.
Один человек без связей даёт 0. Время и память обоих алгоритмов: O(v).
